01SIMPLIFIED TECHNICAL ENGLISH

Precision, without borrowing certainty.

CLARIFIED

“Created in the late 1970s.”

The project began in 1979. The first AECMA Simplified English Guide was published in 1986. ASD-STE100 is its present name; Issue 9 is dated 15 January 2025.

Source: official STE history ↗
VERIFIED, WITH DETAIL

“Under twenty words. One action. One name.”

Rule 5.1 permits a maximum of 20 words in procedural sentences. Rule 5.2 separates instructions per sentence, with an exception for simultaneous actions. Rule 1.11 requires the same technical noun for the same item. “Under 20” and “always one action” are too absolute.

Source: Issue 9, rules 5.1, 5.2 and 1.11 (PDF) ↗
IMPORTANT LIMIT

A short prompt is not STE certification.

STE includes a controlled dictionary and a complete set of writing rules. Borrowing a few principles can guide an edit; full compliance requires more. The official STE group also warns that AI assistance cannot replace human oversight.

Official FAQ ↗STE and AI white paper (PDF) ↗
OVERGENERALIZED

“AI is bad at technical tasks because the writing is murky.”

Unclear prose is one failure mode. Incorrect facts, missing context, faulty reasoning, and untested code are others. Clearer wording makes an answer easier to inspect; it does not make the answer correct.

Editorial assessment. The suggested directive is a technique to try, not a measured performance guarantee. The aerospace safety claim is not used here as proof that AI synonym changes have caused deaths.

02EPHEMERAL TOOLS & VISUAL EXPLANATIONS

Choose a medium for a reason.

UNSUPPORTED RANKING

“Text is the lowest bandwidth format. Interaction teaches ten times more.”

No evidence supplied establishes that universal order or multiplier. Mayer and Moreno describe benefits from relevant words and pictures together. Hegarty, Kriz, and Cate found no animation advantage over static diagrams in their mechanical-system experiments. Design and task matter.

Mayer & Moreno, 2002 (PDF) ↗Hegarty, Kriz & Cate, 2003 (PDF) ↗
OVERSTATED

“The marginal cost of generated code is essentially zero.”

Code generation uses computation and may incur usage charges. Verification, debugging, integration, and maintenance still take work. Small tools can be economical without being free. Custom scripts and one-off software also existed before generative AI.

Example primary source: model usage pricing ↗
ATTRIBUTION UNCONFIRMED

The Karpathy quote about discardable artifacts.

Secondary reproductions attribute the idea to Andrej Karpathy. The original post could not be retrieved in this review. We therefore do not present its wording as a verified quotation, or its format preference as experimental evidence.

Reported original post; content not independently verified ↗
DEFINED & CHECKABLE

“A learning rate of 1.5 causes divergence.”

That depends on the objective. For f(x) = x², xₙ₊₁ = (1 − 2η)xₙ. At η = 1.5, each step multiplies x by −2. The magnitude grows. For f(x) = ½x², that same learning rate would converge.

ANECDOTE, NOT A BENCHMARK

“Thirty seconds to generate. Ten seconds to understand.”

Those are personal timings, not reproducible promises. They do not establish a general learning speed or a reliable time to generate an explanation.

SOURCE CHECK

Review the behavior, not the star count.

Static review on 21 October 2026 covered manifests, relevant skill instructions, local script calls, hooks, and MCP configuration. No obvious malicious behavior was found in the reviewed writing paths. We did not install the plugins, run their code, audit remote services, or test release binaries. This is not a security certification.

Findings and exact source versions

Stayux Clear Answer: The Python linter uses the standard library and reads stdin plus optional local dictionaries. No network or subprocess calls were found in that linter. The duplicate checker reads local skill headers; /init edits CLAUDE.md. Pass untrusted text through a file or stdin without interpolating it into shell commands. Reviewed source: bebc8ff ↗

Writing Skills: The writing skills are Markdown instructions. No runtime executable scripts, hooks, MCP configuration, or credential requests were found in the reviewed skill package. Repository validation and publishing tools are separate. Reviewed source: 2e692b8 ↗

STE Explain: Its skill folder contains two Markdown files with no runtime code or dependencies. The repository also has development scripts and a local validation hook; the skill folder does not include them. Reviewed source: f2dd1d8 ↗

HasData: Configures a remote MCP connection to mcp.hasdata.com. Queries, URLs, and any supplied request data leave Claude for that service. Its session hook prints routing instructions. It includes prompt-injection and credential-handling guidance, but these are instructions, not enforced protection. Optional CLI installation introduces a separate binary that we did not audit. CLI examples place keys in command arguments or environment variables; prefer interactive configuration and avoid secrets in shell history. Reviewed source: 0423a81 ↗

These findings apply to the linked source snapshots. Recheck changes before updating. We use no minimum-star safety threshold.
