Style odpowiedzi w Claude Code

Kształtuj każdą odpowiedź.
Ton ustaw raz.

Styl odpowiedzi określa, jak Claude Code odpowiada przez całą sesję: długość, ton i format. Zmienia instrukcje, które dostaje Claude, a nie to, co Claude wie o Twoim projekcie.

Concise
Zaczyna od wyniku i pomija wstępy, komentowanie bieżących działań i podsumowania. Błędy, ostrzeżenia i wszystko, co każesz rozwinąć, podaje w całości.
Explanatory
Dodaje krótkie notatki Insight z uzasadnieniem każdego wyboru.
Learning
Wyjaśnia swoje wybory i zostawia Ci do napisania małe fragmenty kodu.
Proactive
Od razu zaczyna pracę i zamiast zadawać rutynowe pytania, przyjmuje rozsądne założenia.

Wszystkie cztery zachowują standardowe instrukcje programistyczne Claude Code. Default oznacza brak stylu.

  1. 1

    Przełącz

    W terminalu uruchom /output-style concise. Bez nazwy polecenie wyświetli listę stylów. Możesz też uruchomić /config i wybrać Output style. Polecenie wymaga Claude Code v2.1.269 lub nowszego.

  2. 2

    Aplikacja desktopowa

    Dodaj "outputStyle": "Concise" do .claude/settings.local.json lub, dla wszystkich projektów, do ~/.claude/settings.json. W tych plikach wielkość liter w nazwie ma znaczenie.

  3. 3

    Używaj

    Styl zacznie działać od następnej wiadomości. Aby wrócić, wybierz default.

Własny styl

Zapisz plik Markdown w ~/.claude/output-styles/, aby działał we wszystkich projektach, albo w .claude/output-styles/ dla jednego projektu. Nazwa pliku staje się nazwą stylu. Plik może napisać za Ciebie Claude Code – przejrzyj go przed użyciem. Po utworzeniu lub edycji stylu uruchom Claude Code ponownie.

Przykład: styl w prostym języku
plain-language.md
---
description: Krótkie odpowiedzi codziennym językiem, z objaśnieniem terminów technicznych
keep-coding-instructions: true
---

Pisz dla bystrego czytelnika, który nie jest specjalistą.

- Zaczynaj od odpowiedzi w jednym lub dwóch zdaniach.
- Używaj codziennych słów. Objaśnij termin techniczny, gdy używasz go po raz pierwszy.
- Pisz krótkie zdania. Każdą rzecz nazywaj jednym terminem.
- Gdy mam coś zrobić, podawaj ponumerowane kroki.
- Nie zmieniaj kodu, poleceń, nazw plików, liczb ani ostrzeżeń.
- Gdy o to poproszę, podawaj więcej szczegółów.

Zapisz go jako ~/.claude/output-styles/plain-language.md, uruchom ponownie Claude Code, a potem wpisz /output-style plain-language. Jeśli Claude nadal pisze dla Ciebie kod, zostaw keep-coding-instructions: true. Bez tego ustawienia własny styl pomija wbudowane instrukcje inżynierii oprogramowania Claude Code w pełnym prompcie systemowym. Krótszy prompt systemowy ich nie zawiera, więc tam to ustawienie nic nie zmienia.

CLAUDE.md czy styl odpowiedzi?

CLAUDE.md
Jak Claude ma pracować z Twoim kodem: zakres, prostota, testy i jasny język. Jest wczytywany bez względu na wybrany styl, a plik projektu możesz udostępnić zespołowi.
Styl odpowiedzi
Jak brzmi każda odpowiedź: długość, ton, format albo inna rola, na przykład asystenta pisania. Zmieniasz go jednym poleceniem.

Używaj ich razem. W CLAUDE.md trzymaj zasady pracy. Jeśli odpowiedzi są za długie, zanim napiszesz własny styl, wypróbuj wbudowany styl Concise. Jedno i drugie to instrukcje, którymi Claude się kieruje, a nie gwarancje. Dokumentacja stylów odpowiedzi ↗
