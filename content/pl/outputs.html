Style odpowiedzi w Claude Code

Kształtuj każdą odpowiedź.
Ton ustaw raz.

Styl odpowiedzi określa, jak Claude Code odpowiada przez całą sesję: długość, ton i format. Zmienia instrukcje, które dostaje Claude, a nie to, co Claude wie o Twoim projekcie.

Concise
Gdy odpowiedzi są za długie. Zaczyna od wyniku i pomija wstępy, komentowanie bieżących działań i podsumowania. Błędy, ostrzeżenia i wszystko, o co zapytasz, podaje w całości.
Explanatory
Gdy chcesz wiedzieć dlaczego. Dodaje krótkie notatki Insight o wyborach, których dokonał Claude. Przydaje się przy poznawaniu kodu.
Learning
Gdy chcesz poćwiczyć. Wyjaśnia swoje wybory i zostawia Ci do napisania małe fragmenty kodu.
Proactive
Gdy chcesz mniej pytań. Od razu zaczyna pracę i sam podejmuje rutynowe decyzje.

Wszystkie cztery zachowują standardowe instrukcje programistyczne Claude Code. Default oznacza brak stylu. Zacznij od niego, a styl zmieniaj, gdy masz powód.

  1. 1

    Przełącz

    W terminalu uruchom /output-style, aby wyświetlić listę stylów, a potem wybierz jeden, na przykład /output-style explanatory. Możesz też uruchomić /config i wybrać Output style. Polecenie wymaga Claude Code v2.1.269 lub nowszego.

  2. 2

    Aplikacja desktopowa

    Dodaj "outputStyle": "Explanatory" do .claude/settings.local.json lub, dla wszystkich projektów, do ~/.claude/settings.json. W tych plikach wielkość liter w nazwie ma znaczenie.

  3. 3

    Używaj

    Styl zacznie działać od następnej wiadomości. Aby wrócić, wybierz default.

Własny styl

Zapisz plik Markdown w ~/.claude/output-styles/, aby działał we wszystkich projektach, albo w .claude/output-styles/ dla jednego projektu. Nazwa pliku staje się nazwą stylu. Plik może napisać za Ciebie Claude Code – przejrzyj go przed użyciem. Po utworzeniu lub edycji stylu uruchom Claude Code ponownie.

Przykład: styl zrównoważony
clear.md
---
description: Najpierw odpowiedź, potem tyle szczegółów, ile wymaga zadanie
keep-coding-instructions: true
---

Dopasuj długość do pytania.

- Zaczynaj od odpowiedzi lub wyniku w jednym lub dwóch zdaniach.
- Przy prostym pytaniu na tym poprzestań.
- Przy decyzjach, błędach i zmianach, na które mam zareagować, podaj w całości powody, ryzyka i kolejne kroki.
- Używaj codziennych słów. Objaśnij termin techniczny, gdy używasz go po raz pierwszy.
- Gdy mam coś zrobić, podawaj ponumerowane kroki.
- Nie zmieniaj kodu, poleceń, nazw plików, liczb ani ostrzeżeń.
- Napisz, czego nie udało się zrobić ani sprawdzić.

Zapisz go jako ~/.claude/output-styles/clear.md, uruchom ponownie Claude Code, a potem wpisz /output-style clear. Jeśli Claude nadal pisze dla Ciebie kod, zostaw keep-coding-instructions: true. Bez tego ustawienia własny styl pomija wbudowane instrukcje inżynierii oprogramowania Claude Code w pełnym prompcie systemowym. Krótszy prompt systemowy ich nie zawiera, więc tam to ustawienie nic nie zmienia.

CLAUDE.md czy styl odpowiedzi?

CLAUDE.md
Jak Claude ma pracować z Twoim kodem: zakres, prostota, testy i jasny język. Jest wczytywany bez względu na wybrany styl, a plik projektu możesz udostępnić zespołowi.
Styl odpowiedzi
Jak brzmi każda odpowiedź: długość, ton, format albo inna rola, na przykład asystenta pisania. Zmieniasz go jednym poleceniem.

Używaj ich razem. W CLAUDE.md trzymaj zasady pracy. Zacznij od Default, a styl zmieniaj, gdy masz powód: Concise dla krótszych odpowiedzi, Explanatory, gdy chcesz wiedzieć dlaczego, albo styl Clear powyżej, jeśli odpowiedzi mają być krótkie, gdy to możliwe, i pełne, gdy to potrzebne.
