    SLOWLY EVOLVING

    WHAT THE PROMPT ASKS FOR

    Good technical writing
    leaves less to guess.

    Fluent is not the same as clear. Ask for stable names, direct sentences, and an explicit boundary between evidence and inference.

    01

    Give each thing
    one name.

    If the component is a “worker,” keep calling it a worker. A fresh synonym can look like a different component.

    02

    Give each step
    one action.

    Break a procedure into actions you can perform and check. Put conditions before the actions they control.

    03

    Give each claim
    a clear status.

    Separate what the source says from what the model infers. Keep uncertainty visible. Ask how to verify the answer.

    BEFORE / ILLUSTRATIVE EXAMPLE

    After saving the configuration, you might want to restart the service and check that the worker’s health endpoint returns HTTP 200, restoring the previous configuration if the process fails this check.

    A crowded sentence. Inconsistent names.
    AFTER / A MORE PRECISE BRIEF
    1. Save the configuration.
    2. Restart the worker.
    3. Check the worker’s health endpoint.

    Expected result: HTTP 200. If the check fails, restore the previous configuration.

    One name. Visible steps. A defined result.
