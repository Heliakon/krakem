Claude Code output styles

Shape every reply.
Set the tone once.

An output style tells Claude Code how to answer for a whole session: length, tone, and format. It changes Claude’s instructions, not what Claude knows about your project.

Concise
When answers are too long. Leads with the result and leaves out preamble, narration, and recaps. Errors, warnings, and anything you ask about stay in full.
Explanatory
When you want the why. Adds short Insight notes on the choices Claude made. Good for learning a codebase.
Learning
When you want practice. Explains its choices and leaves small pieces of code for you to write.
Proactive
When you want fewer questions. Starts work at once and makes routine decisions itself.

All four keep Claude Code’s standard coding instructions. Default means no style. Start there, and switch when you have a reason.

  1. 1

    Switch

    In the terminal, run /output-style to list the styles, then pick one, for example /output-style explanatory. Or run /config and choose Output style. The command needs Claude Code v2.1.269 or later.

  2. 2

    Desktop app

    Add "outputStyle": "Explanatory" to .claude/settings.local.json, or to ~/.claude/settings.json for all projects. The name is case-sensitive there.

  3. 3

    Use it

    The style applies from your next message. Choose default to go back.

Make your own

Save a Markdown file in ~/.claude/output-styles/ for all your projects, or in .claude/output-styles/ for one project. The file name becomes the style name. You can ask Claude Code to write the file; review it before you use it. Restart Claude Code after you create or edit a style.

Example: a balanced style
clear.md
---
description: Answer first, with as much detail as the task needs
keep-coding-instructions: true
---

Match the length to the question.

- Lead with the answer or result in one or two sentences.
- For a simple question, stop there.
- For decisions, errors, and changes I must act on, give the reasons, risks, and next steps in full.
- Use everyday words. Define a technical term the first time you use it.
- Use numbered steps when I need to do something.
- Keep code, commands, file names, numbers, and warnings exact.
- Say what you did not do or could not check.

Save it as ~/.claude/output-styles/clear.md, restart Claude Code, then run /output-style clear. Keep keep-coding-instructions: true if Claude still writes code for you. Without it, a custom style leaves out Claude Code’s built-in software engineering instructions on the full system prompt. The shorter system prompt does not include them, so there the setting has no effect.

CLAUDE.md or an output style?

CLAUDE.md
How Claude should work on your code: scope, simplicity, tests, and clear writing. It stays loaded whichever style you pick, and a project file can be shared with your team.
Output style
How every reply reads: length, tone, format, or a different role, such as a writing assistant. You switch it with one command.

Use them together. Keep CLAUDE.md for working rules. Start with Default, then switch for a reason: Concise for shorter answers, Explanatory for the why, or the Clear style above for answers that are short when they can be and complete when they must be.
